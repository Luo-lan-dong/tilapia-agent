# ADR-005：统一文件存储选型

## 状态

Accepted

## 日期

2026-08-03

## 问题背景

OPC 项目涉及大量文件：

- 用户输入的需求文档、参考资料。
- Agent 节点生成的代码工程、视频成片、设计稿、文案、报表。
- 系统运行日志、交付物归档。

文件特点：

- 体积大（视频、代码包）。
- 类型多（文档、图片、视频、压缩包）。
- 需要被多个节点访问（禁止节点间点对点传输）。

## 决策

采用 **MinIO（S3 兼容对象存储）** 作为统一文件存储底座。

## 备选方案

| 方案 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| MinIO（S3 兼容） | 自托管、S3 API 兼容、轻量、可私有化部署 | 需要自行运维 | ✅ 选中 |
| 阿里云 OSS / 腾讯云 COS | 托管服务，稳定可靠 | 增加成本，依赖公网/云厂商 | ❌ 否决 |
| NFS / 本地共享目录 | 简单直接 | 扩展性差，跨机器访问复杂 | ❌ 否决 |
| 数据库 BLOB 存储 | 事务一致性好 | 大文件读写性能差，不适合视频/代码包 | ❌ 否决 |

## 决策原因

1. **私有化部署**：OPC 项目强调节点隔离部署，MinIO 可以部署在私有网络内。
2. **S3 API 标准**：前后端、Agent 节点都可以用统一的 SDK 访问，路径和权限管理标准化。
3. **成本可控**：MVP 阶段自托管 MinIO，无需云存储费用。
4. **扩展性**：后续可平滑迁移到云厂商 S3 兼容服务。

## 影响

- 文件路径命名规范：`opc-bucket/{业务域}/{task_id}/{filename}`。
- 交付物路径：`deliverables/{task_id}/{filename}`。
- 需求资料路径：`requirements/{task_id}/{filename}`。
- 接口中只传递文件路径和元数据，不传输文件内容。
- 前端通过预签名 URL 下载/预览文件。
