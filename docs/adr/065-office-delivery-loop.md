# ADR-065：办公节点交付闭环与能力增强

## 状态

Accepted

## 日期

2026-10-05

## 问题背景

ADR-062 落地了独立办公 Agent 节点（`opc-agent-office`），把办公任务从「中枢技能包」里拆出来，走「一节点一工种」的横向扩展路线。节点骨架、注册/心跳/任务下发、docx/pptx 新建、DDG 检索 + httpx 抓取都已跑通。但 2026-10-05 对 office 节点做的一次**只读代码审计**表明：这条链路目前只能"产出文件"，不能"交付结果"——它既看不全素材、也改不了既有文件，更没有任何东西在交付前检查产物是否达标；同时中枢对它在做什么几乎不可见。

### 审计结论（已核实事实，仅列结论与关键证据）

| # | 结论 | 关键证据 |
|---|------|---------|
| A1 | office 项目**没有任何 Excel 能力**：全仓 `grep xlsx` **零命中** | `opc-agent-office/` 全仓 grep `xlsx` 无结果；`app/tools/` 下无 xlsx 工具 |
| A2 | office 项目**不能读素材**：`read_docx` / `read_pdf` / `read_xlsx` 全部 grep **零命中** | `opc-agent-office/` 全仓 grep 三者均无结果 → 只能凭空新建，无法"基于这份材料改" |
| A3 | 中枢**看不到办公节点在做什么**：`agent_trace` grep **零命中** | `opc-agent-office/` 全仓 grep `agent_trace` 无结果 → 无 status/reasoning/text/tool 上报 |
| A4 | `write_*` 工具**只支持新建**，不支持改既有文件：`app/tools/docx_tool.py`、`app/tools/pptx_tool.py` 仅覆盖标题/段落/表格/图片；pptx 的图表是**占位**（不是真图表） | `app/tools/docx_tool.py`、`app/tools/pptx_tool.py` 的工具签名与实现 |
| A5 | 抓取依赖**声明了但线上从未生效**：`pyproject.toml:27` 声明 `scrapling[fetchers]>=0.4.0`（**无上界**），而 `logs/agent*.log` 里成片出现 `scrapling_not_installed` 与 `scrapling_unavailable_fallback_httpx` → 一直走 httpx 降级路径（无 JS 渲染、无 stealth 反反爬） | `opc-agent-office/pyproject.toml:27`；`logs/agent*.log` |
| A6 | 检索入口仍是**手写正则**解析 DDG/Bing SERP → 结果页一改版就静默失效，且无法退化为结构化解析 | `app/tools/search_tool.py` |
| A7 | checklist **只被拼进提示词**，让 LLM 自称核对 → **无判据、无回灌、无阻断**，属于"假成功"高发区 | `app/executor/office_bridge.py:225` |
| A8 | 进度上报范式**已经存在且够用**，只是没有被扩展成轨迹镜像 | `office_bridge.py:241-244`：`self._callbacks.on_progress(..., stage=, message=)` |

一句话总结：

> **办公节点现在是「一次性的文件生成器」，不是「能交付的办公代理」。**
> 它读不到素材、改不了既有件、做不出真图表，交付前不检查，
> 干活的痕迹中枢也看不见——用户拿到文件只能自己开来看对不对。

### 用户已确认的决策输入（2026-10-05 讨论）

| 编号 | 决策 | 边界 |
|------|------|------|
| D1 | **编辑语义 = 另存新版本** | 读入原文件 → 改 → 输出**新文件**；原文件不动，可回滚；不做原地覆盖 |
| D2 | **验证强度 = L0 结构闸 + L1 内容闸（硬闸）+ L2 语义闸** | L0/L1 硬闸不达标即回灌；L2 由 LLM 按 checklist **逐条判**且**必须给出证据位置** |
| D3 | **模板化（企业模板/母版/品牌色）放第二批** | 本批不做，仅预留接口位 |
| D4 | **独立立项 ADR-065** | 不挂 062 序号，避免 062 的"节点搭建"与本批"能力与闭环增强"混在一份文档里 |

## 决策（Decision）

### 1. 总目标：把「生成」升级为「交付闭环」

办公节点的任务链路收敛为固定闭环：

```
读素材 → 检索/抓取 → 规划 → 产出 → 自验证(L0/L1/L2) → 不过则回灌重做(≤5 轮) → 通过则交付
```

- **产出分两路**：全新文件走 `write_*`；改既有文件走 `edit_*`（D1：**另存新版本**，原文件不动）。
- **自验证分层**（D2）：L0 结构闸 + L1 内容闸为**硬闸**，L2 语义闸为 LLM 逐条判定。
- **回灌重做 ≤5 轮**，且**只修不达标项**（不重做已达标部分，避免越改越差与 token 浪费）。
- **5 轮不过 → `verify_blocked` 阻断**：复用中枢**既有阻断态**、**既有前端决策入口**、**既有 24h 兜底**机制，不新造状态机。
- **全程落 `task_agent_trace`**，使中枢（及后续 `@节点` 会话）能实时看到节点在做什么。

### 2. 判据来源（关键约束）

**判据必须来自中枢派发的任务规格 / checklist**，节点不得自造判据。

- 节点从任务规格中读取 checklist 条目，作为 L2 的逐条判据；
- **主观项（排版美观、语气风格等）不做硬判**，标记为「需人工决策」并随交付物一并回传，交由人在前端决策入口处理；
- 「无法验证」也必须显式呈现，**不得伪装成正常通过**（与 ADR-061 M4「从严、不许假成功」同口径）。

### 3. 模块拆分与推进纪律

沿用 ADR-061 的推进纪律：**一个模块一个模块完成，一次只做一个模块，逐个验收**；本 ADR 只固化设计，不写代码。

## 备选方案（Considered Options）

| 方案 | 结论 | 原因 |
|------|------|------|
| A. 让 LLM 继续"自称核对"checklist（现状） | ❌ 否决 | 无判据、无回灌、无阻断，属于**假成功**高发区；用户明确不接受"看着像完成"的交付（A7） |
| B. 只做 L0 结构闸（文件能打开、有段落/表格） | ❌ 否决 | 结构完整≠内容正确；「要求的三个小节少了一个」「表格数字与素材不符」这类错误 L0 全部漏过 |
| C. 用**确定性脚本**做全部验证（不引入 L2 语义闸） | ❌ 否决 | 办公任务的核心判据是语义性的（是否覆盖了 checklist 的每条要点、结论是否与素材一致），无法用正则/结构断言表达；强行脚本化会退化成脆弱的字符串匹配 |
| D. **原地覆盖编辑**既有文件 | ❌ 否决 | 用户明确选择"另存新版本"（D1）：覆盖不可回滚，一次误改就毁掉用户原件 |
| E. 模板化（企业模板/母版/品牌色）并入本批 | ⏸️ 延后 | 用户决策 D3 放第二批：本批先把"读得进、改得动、验得过、看得见"跑通，模板属于样式层增益 |
| F. 把本批内容并入 ADR-062 追加章节 | ❌ 否决 | 062 已完成并 Accepted，主题是"节点搭建"；本批是"能力与交付闭环增强"，混写会让 062 变成长期滚动的巨型文档（D4） |
| G. 自建搜索/抓取栈替换 Scrapling | ❌ 否决 | 重复造轮子；当务之急是**把已声明的依赖真正装上**并锁版本、把正则解析换成结构化解析器（A5/A6） |

## 影响

### 对系统架构的影响

- office 节点从「文件生成器」升级为「带交付闸的办公代理」：新增素材读取层、编辑另存层、三层验证层、轨迹镜像层。
- **中枢协议零变更**：复用既有 `on_progress`（stage 封闭枚举）、既有 `task_result` 交付物回传、既有阻断态与前端决策入口；不新增事件类型。
- 轨迹上报复用 **ADR-064 已定的 `POST /api/v1/tasks/{id}/agent-trace` 契约与 seq 语义**（该端点**无任务状态前置**，仅校验任务存在），因此办公节点可与对话能力共享同一条镜像通道。
- `verify_blocked` 走中枢既有阻断态，调度器**零改动**。

### 对开发/运维的影响

- 工作集中在 `opc-agent-office/`：新增读/写/编辑工具、验证器、轨迹上报、成本护栏；中枢侧仅需确认轨迹端点与阻断态的既有能力可用。
- 依赖治理：`scrapling[fetchers]>=0.4.0`（无上界）改为**锁版本 + 安装探针**，节点启动自检并在缺失时明确上报（不再静默降级而不告警）。
- 成本：新增 L2 语义闸会带来额外 LLM 调用；用**80%/100% 预算护栏（M7）**兜住，超阈值降级或阻断。
- 运维可见性提升：`agent_trace` 落库后，中枢时间线可展示办公节点的 status/reasoning/text/tool。

### 对安全的影响

- 编辑另存语义（D1）**天然防误毁**：原文件全程只读，风险面收敛。
- 素材读取只读打开，不执行文档内宏/脚本；路径仍受任务 `output_dir` 工作目录绑定约束（ADR-028）。
- 轨迹上报内容需脱敏：**不得落入 LLM 凭据、API Key、绝对路径中的敏感段**（沿用 ADR-029「凭据仅内存、不落库不落日志」口径）。
- 联网抓取继续遵守 robots.txt + 限速；stealth 开关默认关闭，按需开启并记录。

## 模块拆分

> 推进纪律：**一次只做一个模块**，做完一个验收一个（ADR-061 同款）。
> 验收方式统一为：**派发真实办公任务**（不是单测桩，也不是肉眼估）。

| 模块 | 名称 | 交付内容 | 验收方式 |
|------|------|---------|---------|
| **M1** | 素材读取 | `read_docx` / `read_xlsx` / `read_csv` / `read_text`（`read_pdf` 可选），统一返回结构化文本 + 元信息 | 派发真实办公任务：给一份 docx + 一份 xlsx，要求"按素材要点汇总"，节点能读出并复述正确内容 |
| **M2** | 表格与编辑另存 | `write_xlsx` + `edit_xlsx` + `edit_docx`（D1：读入→改→输出**新文件**，原文件不动） | 派发真实办公任务：给一份既有 docx/xlsx，要求"补充第 3 节 / 追加一行汇总"，产出新文件且**原文件字节未变** |
| **M3** | 产出增强 | docx 目录/页码/页眉页脚；pptx 真图表（替换占位）/演讲者备注；matplotlib 生成图表并嵌入 | 派发真实办公任务：要求"生成带目录页码的报告 + 含真实数据图表的 PPT"，打开产物肉眼可见目录/页码/图表数据正确 |
| **M4** | 交付质量闸 | L0 结构闸 + L1 内容闸（硬闸）+ L2 语义闸（LLM 按 checklist 逐条判 + 证据位置）；不过则**只修不达标项**回灌 ≤5 轮；5 轮不过 → `verify_blocked` | 派发真实办公任务：故意给一份会缺项的 checklist，观察回灌轮次、只修不达标项、5 轮后进入 `verify_blocked` 且前端决策入口可见 |
| **M5** | 轨迹镜像 | `agent_trace` 上报 status/reasoning/text/tool；修 `session_id` 合成 | 派发真实办公任务：任务运行中在中枢时间线能实时看到办公节点的 status/reasoning/tool，且 `session_id` 稳定不跳变 |
| **M6** | 检索闭环 | 安装探针 + 锁版本 + stealth 开关；**Scrapling 结构化解析器替换手写正则**；抓取结果做「引用 ↔ 段落」映射 | 派发真实办公任务：要求"查资料并给出带引用的结论"，产物中每条引用能对应到正文段落，日志中无 `scrapling_not_installed` |
| **M7** | 成本护栏 + 收尾 | 预算 80%（软）/100%（硬）阈值；超软阈值告警降级、超硬阈值阻断；文档与安装脚本收尾 | 派发真实办公任务：构造超预算任务，80% 时出现告警/降级、100% 时阻断并明确上报原因 |
