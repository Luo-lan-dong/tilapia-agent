# ADR-007：前端管理控制台仪表盘

## 状态

Accepted

## 日期

2026-08-04

## 问题背景

第二阶段已完成中央调度中枢的后端核心能力：任务创建、Agent 节点注册、任务调度、Mock Agent 执行。用户需要一个可视化的管理控制台来：

- 查看集群整体运行状态（任务、节点）。
- 提交自然语言需求创建任务。
- 实时观察任务从创建到完成的流转过程。

本 ADR 决策第四阶段前端仪表盘的最小范围、技术实现方式以及与后端的集成策略。

## 决策

1. **先实现最小化仪表盘**：只做 `index.html` 设计稿中的核心模块，后续页面（节点管理详情页、任务队列详情页、告警中心、日志审计、设置等）延后。
2. **数据获取优先使用 REST API 轮询**：MVP 阶段先通过定时轮询获取任务列表和节点列表，避免引入公共 WebSocket 通道的复杂度。
3. **后端补充必要的列表接口**：新增 `GET /api/v1/tasks` 和 `GET /api/v1/agent-nodes`，为前端仪表盘提供数据。
4. **前端项目独立**：使用 `opc-web-console/` 目录，与后端解耦，独立启动和部署。
5. **UI 风格遵循设计稿**：深色主题、信息密度、组件形态参考 `opc-central-dispatch-hub/pages/index.html`，但使用 Ant Design 组件重新实现，不直接照搬 HTML/CSS。

## 备选方案

| 方案 | 描述 | 优点 | 缺点 | 决策 |
|---|---|---|---|---|
| A. REST 轮询 | 每 3~5 秒轮询任务列表和节点列表 | 实现简单、调试方便、与现有后端兼容 | 实时性稍差、有一定请求量 | ✅ 选中 |
| B. WebSocket 实时推送 | 前端直接连后端 WebSocket 接收任务进度 | 实时性最好、延迟低 | 需新增前端公共事件通道、增加后端复杂度 | ❌ 延后 |
| C. 先做完整管理后台 | 一次性实现仪表盘、节点管理、任务队列、告警、设置 | 功能完整 | 开发量大、调试复杂、违背最小化原则 | ❌ 否决 |

## 影响

- 新增 `opc-web-console/` 前端项目。
- 后端新增两个列表查询接口，保持与现有 API 规范一致。
- 前端与后端通过 `VITE_API_BASE_URL` 环境变量配置联调地址。
- 文件长度、命名、组件拆分需遵守 `docs/standards/coding-standards.md`。
