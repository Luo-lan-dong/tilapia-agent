# 2026-10-05 节点离线排查：注册竞速超时（1s）在高 RTT 网络下必挂

## 现象

- 两台 code 节点（192.168.101.104 笔记本 / 192.168.101.13）在中枢页面显示离线；
- DB `agent_nodes.last_heartbeat_at` 停在 2026-10-03 18:09 UTC（两台**同一秒**停）；
- 节点侧 `journalctl` 每 5 秒一条 `websocket_session_failed error=`（**error 为空**），`node_id=None`，永远连不上。

## 根因链（两个因素叠加）

1. **诱因**：中枢所在 Windows 机于 10-04 02:09（节点本地时间）睡眠/关机，WS 断开；恢复后节点持续重试。
2. **放大器（真正的 bug）**：节点 agent 的注册竞速超时写死 `PROBE_TIMEOUT_SECONDS = 1.0`
   （`app/client/endpoint_probe.py`）。当前网络形态是「节点 →VPN(10.0.0.x)→ 中枢 →VPN→ 数据库(192.168.101.101)」，
   hub 每次查库往返 ~200ms，注册接口（select + update + commit 多次往返）端到端实测 **2.6s**：
   - 本机直连 hub 实测 `POST /api/v1/agent-nodes/register` = 201，耗时 2.56~2.84s；
   - agent 侧 1s 必超时 → `TimeoutError`（str 为空 → 日志 `error=` 空无从排查）→ 永远注册不上 → 离线。
   - 以前在线是因为当时网络 RTT 低；网络形态一变即触发。

## 修复

| 项 | 内容 |
|---|---|
| 代码 | `endpoint_probe.py` 竞速超时 `1.0 → 10.0`（竞速并行发起，放宽不影响快端点胜出）；`hub_client.py` 失败日志补 `type(exc).__name__`（修复 `error=` 空排查陷阱） |
| 版本 | `opc-agent-code-0.6.0-linux-x64.tar.gz`（构建于 101.101，含 ADR-063 M2 轨迹采集） |
| 发布 | 两台节点停服务 → 替换 `bin/opc-agent`（旧版备份 `.bak`）→ 重启。注意：**服务运行中 cp 会"文本文件忙"失败，必须先 stop** |
| 结果 | 两节点 `register 201 → websocket_connected`，DB 状态 busy / idle，心跳刷新 |

## 经验

1. 节点日志 `error=` 空基本等于 `TimeoutError`——本次已在代码里补类型名，后续可直接看到 `TimeoutError`。
2. 「中枢与数据库分机 + 高 RTT 链路」会放大所有串行 DB 往返；涉及 DB 的节点侧超时（注册/上报）给足余量。
3. 排查节点离线的固定动作：节点 `journalctl -u opc-agent-code` 看重连错误形态 + 节点 `curl` hub 查库端点测分段时间。
