# ADR-065 Spec：办公节点交付闭环与能力增强

> 对应 ADR：[ADR-065 办公节点交付闭环与能力增强](../adr/065-office-delivery-loop.md)
> 本 Spec 只描述设计与验收口径，**不含代码改动**。

## 1. 功能描述

办公节点（`opc-agent-office`）当前只能"凭空新建 docx/pptx 并检索网页"，交付前不做任何检查，中枢也看不到它在做什么。本批把这条链路升级为**可交付的办公代理**，功能面分为七块：

| 编号 | 功能块 | 功能描述 |
|------|--------|---------|
| F1 | 素材读取 | 提供 `read_docx` / `read_xlsx` / `read_csv` / `read_text`（`read_pdf` 可选），把用户给的素材读成结构化文本 + 元信息，作为后续规划与改写的输入 |
| F2 | 表格与编辑另存 | 新增 `write_xlsx`（新建 Excel）；新增 `edit_xlsx` / `edit_docx`，语义为 **D1 另存新版本**：读入原文件 → 修改 → 输出**新文件**，**原文件保持不动**，可回滚 |
| F3 | 产出增强 | docx 支持目录/页码/页眉页脚；pptx 支持**真图表**（替换现有占位实现）与演讲者备注；支持用 matplotlib 生成图表并嵌入 docx/pptx |
| F4 | 交付质量闸 | 产出后自动自验证：**L0 结构闸** + **L1 内容闸（硬闸）** + **L2 语义闸**（LLM 按 checklist 逐条判且**必须给出证据位置**）；不过则**只修不达标项**回灌重做，**≤5 轮**；5 轮不过进入 `verify_blocked` 阻断 |
| F5 | 轨迹镜像 | 通过 `agent_trace` 上报 `status` / `reasoning` / `text` / `tool`，并修复 `session_id` 合成，使中枢能实时看到办公节点"在做什么" |
| F6 | 检索闭环 | 修 `scrapling[fetchers]>=0.4.0`（无上界）导致的线上从未生效问题：加**安装探针**、**锁版本**、**stealth 开关**；用 **Scrapling 结构化解析器替换手写正则**；抓取结果建立**引用 ↔ 段落映射** |
| F7 | 成本护栏 | 预算 **80%（软）** 告警/降级、**100%（硬）** 阻断，防 L2 语义闸带来的额外调用失控 |

### 闭环主链路

```
读素材 → 检索/抓取 → 规划 → 产出 → 自验证(L0/L1/L2) → 不过则回灌重做(≤5 轮) → 通过则交付
```

关键约束：

1. **产出分两路**：全新文件走 `write_*`；改既有文件走 `edit_*` 且**另存新版本**（原文件不动）。
2. **判据必须来自中枢派发的任务规格 / checklist**，节点不得自造判据。
3. **主观项（排版美观、语气风格）不硬判**，标记「需人工决策」随交付物回传。
4. **「无法验证」不得呈现为正常完成**（与 ADR-061 M4 从严口径一致）。
5. **5 轮不过 → `verify_blocked`**：复用中枢既有阻断态、既有前端决策入口、既有 **24h 兜底**，不新造状态机。
6. **全程落 `task_agent_trace`**，使中枢可见。

## 2. 用户故事

| # | 角色 | 故事 | 对应功能 |
|---|------|------|---------|
| US1 | 用户 | 作为用户，我把一份现成的 Word 和周报 Excel 交给节点，说"按这些素材写一份季度总结"，**节点能真的读出里面的数据和结论**，而不是凭空编一份 | F1 |
| US2 | 用户 | 作为用户，我给一份既有合同 docx 说"补一节违约条款"，**节点产出的是新版本文件，我的原文件一个字节都没变**，改坏了我能直接回滚 | F2 |
| US3 | 用户 | 作为用户，我要一份"带目录、带页码、带页眉页脚的正式报告"和"图表能反映真实数据的 PPT"，**节点交付的产物打开就是对的**，不用我手动补页码或把占位图换成图表 | F3 |
| US4 | 用户 | 作为用户，我担心"看起来完成了其实没做完"，**节点在交付前会自己按我的 checklist 逐条核对，并告诉我每条的证据在哪**；核对不过它会自己重做，而不是把半成品丢给我 | F4 |
| US5 | 用户 | 作为用户，我在中枢页面上**能实时看到办公节点正在干什么**（在写哪一节、调了什么工具、为什么这么改），而不是盯着一个转圈图标 | F5 |
| US6 | 用户 | 作为用户，我要求"查资料后给结论并标明出处"，**节点给出的每条引用都能对应到正文具体段落**，我点得进去核 | F6 |
| US7 | 用户 | 作为用户，当任务连续 5 轮都达不到我的 checklist，**我希望它停下来明确告诉我"卡在哪一条"并让我决策**，而不是无限烧 token 或假装成功 | F4 / F7 |
| US8 | 用户 | 作为用户，我不希望一个办公任务悄悄烧掉大量 token；**到 80% 我能收到提醒、到 100% 它会停下来说清原因** | F7 |

## 4. 降级链路

> 统一口径：**任何降级都必须显式上报**（进度/轨迹中带明确 reason），**不得静默降级后仍呈现为正常完成**。

| # | 降级触发 | 触发信号 | 降级行为 | 上报要求 | 是否会阻断 |
|---|---------|---------|---------|---------|-----------|
| **D1** | **检索不可用**（DDG/Bing 结果页改版、被拦、网络不通） | 检索返回空/异常 | 降级为「仅用已给素材 + 模型既有知识」继续产出；不编造引用 | `stage=searching` 上报 `reason=search_unavailable` | 否（L2 会因缺引用判不过则回灌；仍不过则阻断） |
| **D2** | **素材解析失败**（加密文档、损坏文件、未知格式） | 读取抛错或不支持的扩展名 | 跳过该素材继续，并在交付物中显式标注「该素材未能读取」；请求人工补件 | 上报 `reason=material_parse_failed` + 素材名 | 否；若**全部**素材均失败 → 直接 `verify_blocked` |
| **D3** | **图表生成失败**（matplotlib 缺字体/数据非法/渲染异常） | 渲染异常或输出为空 | 降级为「表格 + 文字说明」，**不使用占位图冒充真图表**；保留数据表 | 上报 `reason=chart_render_failed` | 否；若 checklist 明确要求图表 → L1 判不过并回灌 |
| **D4** | **验证不过**（L0/L1/L2 任一不达标） | 验证器返回未通过 | **只修不达标项**回灌重做，`retry_round` +1；**≤5 轮** | 每轮上报 `stage=summarizing` + 未通过条目 | 是：**5 轮仍不过 → `verify_blocked`** |
| **D5** | **预算耗尽** | 用量达 80% / 100% 阈值 | 80%：软告警 + 关闭 L2 的重复复判等非必要调用（降级为只跑 L0/L1）；100%：硬阻断，停止继续调用 LLM | 上报 `reason=budget_soft_exceeded` / `budget_hard_exceeded` + 当前用量 | 是（100% 硬阻断，进入阻断态） |
| **D6** | **Scrapling 缺失**（未安装 / 安装但版本不符 / `scrapling install` 未跑） | 安装探针自检失败 | 降级 httpx（现状路径）：**无 JS 渲染、无 stealth**，抓取结果质量下降；同时**必须告警**（现状是成片静默 `scrapling_not_installed`） | 启动时 + 每次抓取前上报 `reason=scrapling_not_installed` | 否；若任务强依赖 JS 页面 → L2 判不过并回灌/阻断 |
| **D7** | **轨迹上报不可达**（中枢端点不可用） | `agent_trace` 上报失败 | 本地缓冲后重试，**不阻塞主链路**（轨迹是旁路，不是交付前提） | 本地日志记录上报失败次数 | 否 |

## 5. 验收标准

> 统一验收方式：**派发真实办公任务**（不使用纯单测桩代替端到端验收）。

### 5.1 逐模块验收

| 模块 | 验收动作（可执行） | 通过判据（程序或肉眼可判） |
|------|------------------|--------------------------|
| M1 素材读取 | 派发真实办公任务：上传 1 份 docx + 1 份 xlsx，要求"按素材要点汇总" | ① 节点读出的文本包含素材中**至少 3 个独有事实**（不与公开常识重合的专有名词/数字）；② 汇总结果中这些事实**准确无误**；③ 日志无 `parse_failed` |
| M2 表格与编辑另存 | 派发真实办公任务：给既有 docx 与 xlsx，要求"补充第 3 节 / 追加一行汇总" | ① 产出**新文件**且可正常打开；② 新增内容存在；③ **原文件 SHA256 与任务前完全一致**（程序判定）；④ 产物名与原件不同 |
| M3 产出增强 | 派发真实办公任务：要求"带目录/页码/页眉页脚的 docx + 含真实数据图表的 pptx" | ① 肉眼可见目录、页码、页眉页脚；② pptx 图表**非占位**（图表数据与给定数据一致）；③ 图表由 matplotlib 生成且嵌入；④ 演讲者备注存在 |
| M4 交付质量闸 | 派发真实办公任务：给一份**故意含缺项**的 checklist | ① 节点识别出缺项并回灌；② 回灌**只改不达标项**（已达标段落内容不变）；③ `retry_round` 严格 ≤5；④ 第 5 轮仍不过 → 进入 `verify_blocked`；⑤ 前端**既有决策入口**可见且带"卡在哪一条"；⑥ 24h 兜底生效 |
| M5 轨迹镜像 | 派发真实办公任务，任务运行中观察中枢时间线 | ① 能实时看到 `status` / `reasoning` / `text` / `tool`；② `session_id` 全程**稳定不跳变**；③ 轨迹端点使用 `POST /api/v1/tasks/{id}/agent-trace`，seq 递增无空洞 |
| M6 检索闭环 | 派发真实办公任务："查资料并给带引用的结论" | ① 产物中**每条引用都能对应到正文具体段落**（引用↔段落映射成立）；② 日志中**不再出现** `scrapling_not_installed`（探针通过时）；③ 检索解析走 Scrapling 而非手写正则（代码层面可查）；④ 抓取遵守 robots.txt 且有速率限制 |
| M7 成本护栏 | 派发真实办公任务：构造会超预算的任务 | ① 达 80% 出现软告警并降级；② 达 100% 硬阻断并停止 LLM 调用；③ 阻断时上报明确 reason 与当前用量 |

### 5.2 闭环与约束验收（横向）

| # | 验收项 | 通过判据 |
|---|-------|---------|
| V1 | 判据来源正确 | 节点使用的 checklist **逐条可回溯**到中枢派发的任务规格（不存在节点自造判据） |
| V2 | 主观项不硬判 | 排版美观/语气类条目在结果中标记 `needs_human`，**不计入**硬闸失败 |
| V3 | 无假成功 | 「无法验证」的情况在交付物与轨迹中**显式标注**，绝不呈现为"正常完成" |
| V4 | 降级可观测 | 触发 D1–D7 任一降级时，日志/轨迹中存在对应 reason，**不存在静默降级** |
| V5 | 原文件不可变 | 所有 `edit_*` 任务后，原文件校验和不变（D1 语义成立） |
| V6 | 阻断复用 | `verify_blocked` 使用中枢**既有**阻断态与前端决策入口，未新增状态机字段 |

## 6. 边界（与 ADR-064 的关系）

- 本 Spec **不重复实现** ADR-064 的 `@节点` 续聊会话能力（对话/事件契约/会话生命周期属于 064）。
- 本 Spec 只**对齐** 064 已定的轨迹上报契约：`POST /api/v1/tasks/{id}/agent-trace` 与 seq 语义；该端点**无任务状态前置，仅校验任务存在**。
- 本批**不做**模板化（企业模板/母版/品牌色），留待第二批。
