# 中央调度中枢模块 Spec

## 1. 功能描述

中央调度中枢是 OPC 系统的唯一调度核心，不执行具体业务任务，负责：

- 接收用户自然语言需求，并通过**任务规划 Agent** 调用 DeepSeek 模型完成需求解析。
- 通过任务规划 Agent 调用 DeepSeek 模型，将复合任务拆解为可独立执行的子任务。
- 管理 Agent 节点的注册、心跳、负载与状态。
- 根据任务类型、节点能力、负载状态匹配最优执行节点。
- 下发任务、聚合进度、处理异常、迁移失败任务。
- 汇总各节点交付物，生成完整项目成果。

## 2. 用户故事

- 作为 OPC 用户，我希望用自然语言提交需求，系统自动拆解并分配给合适的 AI 员工执行。
- 作为用户，我希望实时查看任务进度和各子任务状态。
- 作为用户，我希望高风险任务（如代码上线、合同定稿）在执行前需要我确认。
- 作为系统，我希望节点离线时自动迁移未完成任务，保证任务不丢失。

## 3. 核心流程

### 3.1 标准任务闭环

```
用户提交需求
    ↓
[任务规划 Agent] 调用 DeepSeek 模型
    ↓
[需求解析] 识别任务类型、输出标准
    ↓
[任务拆解] 拆分为子任务（串行/并行）
    ↓
[任务调度引擎] 匹配可用 Agent 节点
    ↓
[任务队列] 下发任务及资源路径
    ↓
Agent 节点执行
    ↓
[进度聚合] 实时汇总进度
    ↓
Agent 上传交付物
    ↓
[结果校验/聚合] 生成完整交付包
    ↓
用户查看/确认/归档
```

### 3.2 节点离线迁移流程

```
中枢检测心跳中断
    ↓
标记节点离线
    ↓
查询该节点上未完成任务
    ↓
筛选同类型在线空闲节点
    ↓
迁移任务到新节点
    ↓
通知用户/记录日志
```

### 3.3 任务规划 Agent

任务规划 Agent 是中枢内部的一个服务模块，负责将用户的自然语言需求转换为结构化任务。MVP 阶段只对接 DeepSeek 模型。

#### 3.3.1 职责边界

| 职责 | 归属 | 说明 |
|---|---|---|
| 理解自然语言需求 | 任务规划 Agent + DeepSeek | 由 DeepSeek 解析用户意图 |
| 输出任务类型 | 任务规划 Agent + DeepSeek | DeepSeek 返回 `agent_type`，如 `programming`、`design`、`copywriting`、`video` |
| 拆解子任务 | 任务规划 Agent + DeepSeek | 复杂需求拆分为多个可并行或串行的子任务 |
| 选择执行节点 | 任务调度引擎 | 基于节点能力、在线状态、负载做确定性匹配，不由 LLM 决策 |
| 下发任务 | 任务调度引擎 | 通过 WebSocket 向节点发送 `hub.task_dispatch` 事件 |

#### 3.3.2 DeepSeek 输出格式

任务规划 Agent 调用 DeepSeek 后，应解析为以下结构：

```json
{
  "task_name": "官网落地页前端开发",
  "description": "基于设计稿实现响应式官网落地页，包含 Hero 区和表单区",
  "agent_type": "programming",
  "subtasks": [
    {
      "task_name": "搭建项目结构",
      "description": "初始化 React + Vite 项目",
      "agent_type": "programming",
      "depends_on": []
    }
  ]
}
```

MVP 阶段可先不支持 `subtasks`，一个需求只生成一个任务。

#### 3.3.3 失败降级

- DeepSeek 调用失败：返回错误，要求用户重试或简化需求。
- DeepSeek 返回无法识别的 `agent_type`：标记为解析失败，返回用户确认。
- 返回结果缺少必要字段：由任务规划 Agent 补齐默认值或返回用户补充。

## 4. 降级链路

| 异常场景 | 降级策略 |
|---------|---------|
| 需求解析失败 | 返回用户确认，要求补充关键信息 |
| 无可用 Agent 节点 | 任务进入等待队列，定时重试，超时告警 |
| 任务执行失败 | 自动重试 1 次，仍失败则冻结并推送人工核查 |
| 节点离线 | 任务迁移至同类型空闲节点 |
| 任务超时 | 暂停任务，判定续跑/迁移/终止 |
| 交付物校验失败 | 标记任务失败，通知用户和对应 Agent |

## 5. 验收标准

- [ ] 用户可通过前端提交自然语言需求并收到任务 ID。
- [ ] 中枢能正确拆解「开发官网 + 制作短视频」为两个并行子任务。
- [ ] 中枢能根据 `agent_type` 和负载选择最优节点。
- [ ] 任务状态变化实时推送到前端。
- [ ] 节点离线 30 秒内，未完成任务自动迁移。
- [ ] 高风险任务必须人工确认后才标记完成。
- [ ] 所有关键操作记录可审计日志。
