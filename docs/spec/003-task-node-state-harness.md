# 任务与节点状态管理模块 Harness

## 1. 测试金字塔

```
        /\
       /  \
      / E2E \          少量：完整任务生命周期状态变更
     /--------\
    /  集成测试  \       中量：状态持久化 + 事件触发
   /--------------\
  /    单元测试     \      大量：状态机转换、并发控制
 /------------------\
```

## 2. 单元测试清单

| 测试对象 | 测试场景 | 通过标准 |
|---------|---------|---------|
| 任务状态机 | pending → assigned | 允许 |
| 任务状态机 | running → completed | 允许 |
| 任务状态机 | completed → running | 拒绝，抛异常 |
| 任务状态机 | failed → running（重试） | 允许 |
| 节点状态机 | offline → idle | 允许 |
| 节点状态机 | idle → busy | 允许 |
| 节点状态机 | busy → offline | 允许，同时触发任务迁移 |
| 并发状态更新 | 两个请求同时更新同一任务 | 数据库行锁保证一致性 |

## 3. 集成测试清单

| 测试对象 | 测试场景 | 通过标准 |
|---------|---------|---------|

| 任务完成状态 | 节点上报完成 | 状态变为 completed，记录完成时间 |

| 状态变更事件 | 状态变化 | 触发对应 WebSocket 事件 |

## 5. E2E 测试场景

### 场景 1：任务状态完整流转

1. 用户创建任务。
2. 任务状态：`pending`。
3. 中枢分配给编程 Agent：`assigned`。
4. Agent 开始执行：`running`。
5. Agent 上报完成：`completed`。
6. 用户确认高风险交付物：`archived`。

### 场景 2：节点状态影响任务分配

1. 编程 Agent A 在线空闲。
2. 任务 1 分配给 A，A 状态变为 busy。
3. 任务 2 创建，中枢只能分配给空闲节点。
4. 若无其他空闲编程 Agent，任务 2 进入等待队列。
5. A 完成任务后恢复 idle，任务 2 再分配。

## 6. CI 门禁

- 状态机单元测试覆盖率 ≥ 85%。
- 并发状态更新测试通过。
- 数据库迁移脚本与模型一致。
- ruff / black / mypy 检查通过。
