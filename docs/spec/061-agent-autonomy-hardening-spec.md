> 关联：[ADR-061](../adr/061-agent-autonomy-hardening.md) · [Harness](./061-agent-autonomy-hardening-harness.md) · [Changes](./061-agent-autonomy-hardening-changes.md)

## 1. 现状基线（审计结论展开）

节点真实链路 = **V2 会话核心**（`tilacode/packages/core/src/session/**`）。
`packages/opencode/src/**` 是 V1 旧路径，**节点不使用**（这一点在 ADR-060 已确认）。

| 结论 | 说明 |
|------|------|
| A1 | 节点 agent 的完整系统提示词 = `BUILD_SYSTEM` 一句话 + system-context 基线（env/日期/AGENTS.md/技能清单）。无工作流、无验证纪律、无完成判据 |
| A2 | V1 的 `default.txt:74-75` 要求「完成后**必须**跑 lint/typecheck/测试」且「不要臆测测试框架，先看 README/代码库」；`codex.txt:49` 还要求「不要问『要不要我跑测试』」。V2 完全不加载这些文件 |
| A3 | V1 在 `edit`/`write`/`apply_patch` 之后把 LSP 诊断追加进工具输出（"LSP errors detected in this file, please fix"）；V2 无此回灌，且 `builtins.ts:26-29` 明确把 LSP 列为待移植 |
| A4 | 「完成」= `step.ended` 后 30s 静默 + 轮询 `session/active` 不活跃 → `completed`。**agent 提前收工会被判成功**；中枢 `_handle_task_completed` 全程不读 `tasks.specification` |
| A5 | 验收清单 `checklist.md` 已由中枢生成、随派发透传、由节点写入 `specs/<标题>-<taskid8>/checklist.md`，提示词只让它「先阅读」，**没有任何代码在完成时读回** |
| A6 | 失败信号质量**已经够用**：bash 合并 stdout/stderr、退出码作为独立文本给模型（"Command exited with code N."）、非零退出不算工具错误、2000 行/50KB 头尾截断 + 全文落盘路径 |
| A7 | `serve` 模式**没有任何权限应答器**；`ask` 在 `Deferred` 上无限等待且无超时；未匹配规则默认 `ask`；拒绝一个请求会连带拒绝同会话所有 pending。节点的 `permission_reply("once")` 事件泵是**唯一**防线，漏事件即卡到 1800s watchdog |
| A8 | V2 无 Doom Loop 检测、无会话级重试（`runner/llm.ts:55,86` 未勾选 TODO）；仅传输层重试 2 次（429/503/504/529 + 5xx） |
| A9 | 中枢对节点执行只有 1800s 时间兜底；token/轮次/花费无预算 |
| A10 | 每任务用量只进 structlog（`task_progress_cache_metrics`），不落库；`tool` 字段解析后从不读取；`detail.files` 既不落库也不记日志；节点 `session_id` 被丢弃 |
| A11 | 中枢只能 `hub.task_cancel`（→ 节点 `bridge.interrupt`）；**不能 steer**，但节点 `send_prompt(delivery="steer")` 已支持 |
| A12 | 1 任务 → 1 节点（`assigned_node_id` 单外键）；V2 无 `task` 工具，`general`/`explore` 子 agent 定义存在但**模型不可达** |

### 1.1 V1 通道 / V2 通道对照（**当前启用 V2**）

**结论：节点执行任务走 V2**（`packages/core/src/session/**`）。证据链：
节点只调 `POST /api/session/{id}/prompt`（`tilacode_client.py:282`）→ server `session.prompt` 处理器 → `SessionV2.Service.prompt`；
节点数据目录 `~/.local/share/tilacode/tilacode-local.db` 为 V2 表结构（`session_context_epoch` / `session_input` / `session_message`）。
旁证：本机 TUI 状态栏显示 **`LSPs are disabled`**，而 LSP 是 V1 才有的能力。

| 维度 | V1（`packages/opencode/src/**`，旧路径） | V2（`packages/core/src/**`，**当前**） |
|------|----------------------------------------|--------------------------------------|
| 系统提示词 | 按模型选 `session/prompt/*.txt`，含验证纪律、工具用法示例、失败重试纪律 | **一句话** `BUILD_SYSTEM`（`plugin/agent.ts:12-13`） |
| system 装配 | `[提示词, env, instructions, mcp, skills]` **join 成一坨**（缓存从 token 0 失效） | 两个独立 SystemPart + 会话级基线冻结 + 增量入历史（见 ADR-060） |
| 子 agent | 完整 `task` 工具（`subagent_type` / 深度限制 `subagent_depth` / 权限继承） | **无 `task` 工具**；`general`/`explore` 定义存在但**模型不可达** |
| 编辑后 LSP | 有：诊断追加进工具输出（`tool/edit.ts:196-201`） | **无**（`builtins.ts:26-29` 列为待移植；实测状态栏 `LSPs are disabled`） |
| 防打转（Doom Loop） | 有，阈值 3 → `permission.ask("doom_loop")` | **无**（`runner/llm.ts:55` TODO） |
| 会话级重试 | 有 `SessionRetry`（5xx 可重试，**无上限次数**） | **无**（TODO）；仅传输层重试 2 次（429/503/504/529+5xx） |
| 工具失败信号 | 退出码只在 `metadata`，**模型看不到** | 退出码作为**独立文本**给模型："Command exited with code N."（更好） |
| 步骤上限命中 | 仍传工具定义 | **清空工具定义** + `toolChoice: "none"` |
| 存储模型 | `message` / `part` 表 | 事件溯源：`event` + `session_message` + `session_context_epoch` |
| 压缩切分 | 按**字符**切半条消息 | 按**消息边界**切分（ADR-060 P4 已改） |

**一句话**：V2 在「缓存友好 + 失败信号」上更强，在「干活纪律 + 防呆 + 子 agent」上退化——
这正是 M1a / M3 / M1b 要补回来的部分（**不是新增能力，是迁移丢件找回**）。

> 开放项（不影响 M1–M7）：本机 `~/.local/share/opencode/opencode.db` 是 V1 表结构且含 `(@explore subagent)` 会话，
> 说明该数据由**更早版本二进制 / 旧入口**产生；V1 代码仍完整保留在仓库中，但不在节点链路上。

## 3. 功能描述（分模块）

### M1a · 干活纪律（提示词）

- **目标**：让 agent 具备「我该验证自己的结果」的行为倾向。
- **交付**：把 V1 的验证纪律移植进 `BUILD_SYSTEM`（`packages/core/src/plugin/agent.ts`），内容要点：
  1. 改完代码要**主动**运行项目已有的 lint/typecheck/测试；
  2. **不要臆测**测试框架或脚本，先看 README / 包配置 / 代码库；
  3. 失败要**读原文**再改，不要重复同一命令；
  4. 不要问用户「要不要我跑测试」——直接跑；
  5. 收工前明确写出：做了什么、验证了什么、还有什么没验证。
- **边界**：只改提示词常量，不改任何控制流；不引入新的模型可见语义分支。
- **验收**：见 §5 M1a。

### M2 · 权限语义收敛（策略由中枢统一下发，工作区外默认不放行）

- **目标**：无人值守下既不存在「等待授权」这种状态，也不给 agent 越界的能力——**默认最小权限：只能在任务工作区内活动**。
- **交付**：
  1. **权限策略由中枢统一生成并随派发下发**（不靠节点本地各写各的，也不依赖 tilacode 内置默认值）→ 落进工作区配置/用户级配置。
  2. **默认策略：工作区内 `allow`；工作区外一律 `deny`**（用户未授权时**不放行**）。`.env` 等敏感文件的读取同样在拒绝之列。
  3. 如需例外（例如包管理器缓存目录、系统库路径），必须由中枢**显式开白名单**，而不是放开整个"工作区外"。
  4. 节点侧应答兜底：除 SSE 推送外，**定期主动拉取 pending 权限请求并按策略应答**，防推送丢失造成挂起。
  5. **拒绝必须带原因并回灌给 agent**（让它知道这条路走不通、换做法），不做静默失败。
  6. 每次自动判定留审计记录（结构化日志 + 事件上报），便于事后追责。
- **边界**：不改 tilacode 权限求值的核心算法（deny 优先、已保存规则最后追加等语义保持不变）。
- **已知权衡**：工作区外 `deny` 可能挡住"装依赖/读系统头文件"这类正常需求 → 用**显式白名单**解决，不要因此把整片工作区外放开。
- **验收**：见 §5 M2。

### M3 · 防打转与会话级重试

- **目标**：模型陷入重复劳动/瞬时故障时，不白烧 token。
- **交付**：
  1. **Doom Loop 检测**（对齐 V1 `processor.ts:29,356-380` 的阈值 3：同工具 + 字节相同入参连续 N 次）→ 本回合不执行，注入一条提示并强制文本作答（V2 无对应能力，需新增）。
  2. **会话级重试**（对齐 V1 `session/retry.ts` 的可重试判定），但**必须加上限**：最大尝试次数 + 总时长封顶，超过则失败并把原因回报中枢。
  3. **无进展检测**（沿用中枢 ADR-058 的思路：连续 N 轮无新信息 → 收尾），在节点侧至少记录可观测信号。
- **边界**：重试只针对可重试错误；`ContextOverflow` 走既有压缩路径，不重试。
- **验收**：见 §5 M3。

### M1b · 编辑后 LSP 回灌

- **前置勘察（必须先做）**：确认 V2 是否保留 LSP 基础设施；若需从 V1 移植 LSP 服务，则本模块升级为独立立项，不塞在 M1 里。
- **交付**：`edit`/`write`/`apply_patch` 成功后，把该文件的诊断错误追加进工具输出文本。
- **降级**：LSP 不可用/超时/无诊断时**静默跳过**（不得让编辑本身失败）。
- **验收**：见 §5 M1b。

### M4 · 可执行验收 + 完成闸 + 失败自修

拆三步，①②③ 先做，④ 依赖 M5a：

- **① 结构化判据**：中枢在生成 `checklist.md` 的同时产出 `verify.json`（`[{id, 描述, 命令, 期望, 层级}]`），随三件套一起下发；`checklist.md` 仍保留给人看。
- **② 分层执行（对应 Q2）**：节点按「最便宜且能证伪」顺序执行，绿了就停：

  | 层级 | 内容 | 超时预算 |
  |------|------|---------|
  | L0 | 类型/语法（`tsc --noEmit`、`python -m compileall`、JSON/YAML 解析） | 30s |
  | L1 | 静态规则（eslint、ruff） | 60s |
  | L2 | 单测（vitest/pytest） | 5min |
  | L3 | 目标构建（`npm run build` 等） | 10min |
  | L4 | 端到端（Playwright 等） | 20min |

  - 判据来源优先级：`verify.json` > 项目自带配置（`package.json` scripts / `pyproject.toml` / `Makefile`）> 按改动文件类型推导的最小检查。
  - 找不到任何可用检查时，**必须显式上报「无法验证」**，不得静默判成功。
- **③ 完成闸（从严——用户明确「**比较怕假成功**」）**：
  - 必过层全绿 → `completed`；
  - 有红 → **不报 `completed`**，进入 ④ 自修；
  - **「无法验证」也不算成功**：以独立状态落库（如 `completed_unverified`，状态名与中枢状态机在实施时定稿）并在任务摘要**显著标记**，前端不得呈现为正常完成；
  - **禁止**在没有任何验证结论的情况下把任务置为 `completed`。
- **④ 失败自修回合预算（依赖 M5a 的 steer 通道）**：红了以后把「失败命令 + 输出尾部 N 行 + 未过判据」作为 steer 提示词回灌，让它自己修，**最多 5 轮（用户指定默认值）**；用尽才 failed，并把失败判据写进 `change_summary`。
- **验收**：见 §5 M4。

### M5 · 预算化、中枢↔节点对话、长任务可见

拆三块：

- **M5a 用量落库 + steer 通道（含用户手动 `@节点` 对话）**：
  1. 每任务用量序列落库（复用 `tool_call_logs`，新增 `kind="llm_usage"`，需迁移扩展 check 约束），字段含 step、in/out/cache tokens、cost、tool、files 数、耗时；
     > ⚠️ **成本维度现状为结构性 0**：V2 runner 发布 `Step.Ended` 时 `cost` 被**硬编码为 `0`**
     > （`packages/core/src/session/runner/llm.ts:331`，该文件内 `cost` 仅此一处），
     > 因此节点上报的 `detail.cost` 与 TUI 的 `$0.00 spent` 恒为 0。
     > **结论：M5b 预算闸默认建立在「步数 / token」维度上**；若要按花费预算，需先补价格计算（模型单价 × tokens）。
  2. 中枢新增 `hub.task_steer` 事件 → 节点 handler → `send_prompt(delivery="steer")`（节点能力已存在）；旧节点收到未知事件必须忽略；
  3. **用户手动定向对话（用户原话：「加个 @ 吧，把节点 @ 出来，然后这段话就是发给他的」）**：中枢输入框支持 `@节点A` 选中运行中的节点 → 把该段文字作为 steer 下发到该节点的活动会话；**回复经 M5c 的镜像回流到中枢可见**，形成"在中枢和节点直接对话"。
- **M5b 预算闸（先软后硬）**：任务级配额（步数 / token / 花费，可配）；**软阈值 80%（用户指定）** 发 `hub.task_steer` 要求**收尾并写 handoff**；硬阈值 100% 走现成 `hub.task_cancel`。
- **M5c 只读镜像 + 双层任务摘要 + 实时**（用户在"按需代理"与"只读镜像"之间**选定镜像**）：
  1. 中枢**落一份只读镜像**（可离线回看、可审计），停止丢弃 `tool` / `detail` / 节点 `session_id`；
  2. 会话视图**默认折叠、可展开**，展开即为该节点上的**完整会话**（与在节点本地查看一致）；
  3. **实时性要求（用户明确）**：能实时看到**那边正在做什么、正在执行哪条命令** → 需要把 `tool` 落库并显示（现状：`tool` 被丢弃，摘要里只有 120 字截断的 `progress_message`），并把 5s 轮询升级为推送（或至少显著缩短间隔）；
  4. **任务摘要分两段（2026-09-28 用户澄清后的最终口径）**：
     - **上段 = 子 Agent 实时状态（保持现状，现有 5 块全留）**：状态 Tag + 任务标题 + 进度条 + 「当前动作」
       + 子 Agent 待办列表 + 空态 —— 数据**全部来自节点上报**
       （`task.status/title/progress/progress_stage/progress_message/todos`，组件 `TaskSummary.tsx`）；
     - **下段 = 中枢编排器自己的待办**（本模块增量，详见 **M5d**）：与子 Agent 的 Todo **同形**，但属于**中枢自己**；
       两段数据源互不覆盖。
  5. 进度时间线 + 用量曲线 + 告警（缓存命中率跌破基线、连续同签名调用、长时间无文件写入）。
- **已决（2026-09-28 用户确认）**：① 上段 = 现有 5 块全留；② 下段 = **中枢编排器自己的待办**（独立为 M5d）；
  ③ 预算**保留双档**——80% 软（收尾）/ 100% 硬（取消）。
  > 修正记录：本 Spec 早前一版把下段写成"中枢规划任务（`tasks.md`）+ 中枢执行待办两个子区"，**系推测，已废弃**；
  > 用户口径为"下段就是中枢编排器自己的待办"，与 `tasks.md`（那是右侧「任务清单」页签的内容）不是一回事。

### M5d · 中枢编排器待办（**全新能力**，可独立实施）

- **目标**：中枢侧也有自己的"待办清单"——它接下来打算做什么、已完成哪些；在任务摘要**下段**与子 Agent 的 todo 并列展示，**实时更新**。
- **现状（已核实，确为"零基础"）**：
  - 中枢 `tasks.todos` 列**只存节点上报内容**（`models/task.py:239` 注释"Agent 实时上报的待办列表"，唯一写入点 `task_event_handler.py:400-413`）；
  - 技能注册表 `app/skills/registry.py`（约 20 个技能）中**没有任何 todo 能力**；
  - 因此没有可复用的中枢待办数据源。
- **交付**：
  1. **中枢侧待办存储**：新列或新表（含 `content` / `status`(pending|in_progress|completed) / 顺序 / 时间戳），与节点上报的 `todos` **物理分离**；
  2. **编排器维护待办的技能 + 提示词引导**：让中枢在编排过程中自行列出/推进/勾选待办（形态对齐子 Agent 的 `todowrite`）；
  3. **任务摘要下段渲染**：与上段视觉分层（上=子 Agent、下=中枢），**实时更新**。
- **边界**：不改动上段现有的节点 todo 链路；不把中枢 todo 混进 `tasks.todos`（否则两段语义会串）。
- **依赖**：无（纯中枢 + 前端，可独立于 M5a/M5c 实施）。
- **已定（2026-09-28 用户确认按推荐）**：中枢待办**由中枢编排器主动维护**——新增一个 `todowrite` 式技能，
  形态对齐子 Agent 的 todo（用户原话"类似子 agent 那种 todo"），而非从编排动作自动派生。
- **验收**：见 §5 M5d。
- **验收**：见 §5 M5。

### M6 · 经验记忆下沉与跨机复用

- **复用**：ADR-050 第三层已实现（`experience_records` 表 + `experience_service` + `record_and_match` + `experience_recall`/`experience_resolve` + `/experience` API + `/memory` 页面）。
- **交付**：
  1. 中枢**先修前置缺口**：`_handle_task_progress` 读取并落库 `tool` 字段（现状解析后丢弃）；
  2. 节点把执行失败（命令非零退出/测试红/工具报错）算成 `error_signature`（**必须复用中枢同一套归一化规则**，否则跨端命中不了），经 `detail` 上报；
  3. `experience_records` 增加 `environment_signature`（OS + arch + 运行时版本），召回时**同环境优先**，跨环境降级为「参考」；
  4. **派发前召回**：按任务类型 + 环境签名取 top N 条 resolved 经验，注入任务提示词（复用既有文档注入槽）；
  5. **定时整理**：按签名聚类 pending 条目 → 产出合并草案 → **人工确认后**才写 resolved（维持 ADR-050「记录全自动、总结半自动」的既定原则，不放开）。
- **验收**：见 §5 M6。

### M7 · 前端视觉反馈

- **目标**：纯命令行开发机上也能让 agent「看见」页面。
- **交付**：
  1. **文本优先（必做，任何模型可读）**：用 Playwright 抓 ARIA/DOM 快照 + 浏览器 console 错误 + 失败网络请求 + HTTP 状态码，作为可断言的验证层（挂到 M4 的 L4）；
  2. **截图作为产物（给人看）**：新增脚本 `opc-web-console/scripts/shoot.mjs`（起服务 → 逐页 `page.screenshot()` → 落到任务产物目录回传）；
  3. **依赖固化**：Linux headless 浏览器所需系统库固化进节点镜像/安装脚本，**不依赖 agent 自己 `apt install`**（服务账号通常无 sudo）；
  4. **可选**：若节点模型支持视觉，把截图经 media 内容块回灌（tilacode V2 消息层支持 `type:"media"`），**前提是先确认所用模型支持图片输入**。
- **验收**：见 §5 M7。

## 4. 核心流程（ASCII）

### M4 的验收闭环（本 ADR 的核心价值）

```
任务下发（含 spec/tasks/checklist + verify.json）
        │
        ▼
   agent 干活（改码 / 跑命令 / 读报错，循环）
        │   ← M1a 提示词要求它自检；M1b 编辑后立刻回灌 LSP 诊断
        ▼
  agent 声明收工 / 静默
        │
        ▼
┌───────────────────────────┐
│  M4③ 完成闸：执行 verify   │
│  L0→L1→L2→L3→L4 逐级跑     │
└───────┬───────────┬───────┘
        │全绿        │有红
        ▼            ▼
   completed    ┌──────────────────────────┐
                │ M4④ steer 回灌失败原文    │
                │ 让它自己修（≤N 轮）       │
                └───────┬──────────┬───────┘
                        │修好       │用尽
                        ▼          ▼
                   completed    failed（附未过判据）
```

### M5 的预算闸（先软后硬）

```
用量落库（每 step 一行）──► 预算判定
                              │
              ┌───────────────┼────────────────┐
              │<80%           │≥80%            │≥100%
              ▼               ▼                ▼
           继续执行     hub.task_steer     hub.task_cancel
                       （要求收尾+handoff）  （现成通道）
```

## 5. 验收标准（按模块，实施时逐条勾）

| 模块 | 验收标准 |
|------|---------|
| **M1a** | ① `BUILD_SYSTEM` 含 5 条纪律要点（单测断言关键短语）；② 同一任务的**模型可见内容**无其他变化（回归）；③ 与 ADR-060 基线（缓存命中率 95.2%）对比：不劣化，且任务时长/步数无异常膨胀 |
| **M2** | ① **权限策略由中枢下发**（节点本地无策略时也生效，可断言下发内容）；② 默认**工作区内 allow、工作区外 deny**——工作区外读写**实测被拒且不挂起**；③ `.env` 等敏感文件读取被拒；④ 显式白名单目录仍可用；⑤ 拒绝时 agent 收到**带原因的反馈**而非静默失败；⑥ 模拟「漏掉权限事件」→ 任务不挂；⑦ 每次自动判定有审计记录；⑧ 不再出现 `ask` 中间态 |
| **M3** | ① 同工具+同参连续 3 次 → 本回合被拦截且模型收到提示；② 可重试错误在**上限内**重试成功；③ 超过上限 → 明确失败并回报原因；④ 不重试 `ContextOverflow`（走压缩） |
| **M1b** | ① 编辑出语法错误 → 工具输出含诊断文本；② LSP 不可用/超时 → 编辑本身仍成功（降级）；③ 无诊断时不产生噪音文本 |
| **M4** | ① checklist 能转成 `verify.json` 且人工可读（保留 md）；② 分层执行顺序与超时生效；③ **故意让验收红 → 任务不报 completed**；④ **「无法验证」也不呈现为正常完成**（独立状态 + 摘要显著标记，用户明确"怕假成功"）；⑤ 红了能自修 **≤5 轮**，修好则 completed、用尽则 failed 且附未过判据；⑥ **不存在"无验证结论却 completed"的路径**（守卫用例） |
| **M5** | ① 每任务用量可在库中查到（含 cache_read 与命中率）；② `hub.task_steer` 能被节点接收并触发收尾；③ 软阈值 **80%** 触发收尾而非硬杀；④ 硬阈值 100% 能取消；⑤ **只读镜像**任务结束后仍可回看完整会话；⑥ 会话视图默认折叠、展开为完整会话；⑦ **实时**看到当前正在执行的命令（`tool` 已落库并渲染）；⑧ **任务摘要分两段**：上段保留现状 5 块（状态/标题/进度条/当前动作/子 Agent 待办）；下段渲染**中枢编排器自己的待办**；两段数据源互不覆盖、互不串位；⑨ 中枢可用 `@节点A` 定向发言且回复回流可见；⑩ 旧节点无异常 |
| **M5d** | ① 中枢能创建/推进/完成自己的待办并**持久化**（与 `tasks.todos` 物理分离，互不污染）；② 任务摘要**下段**渲染中枢待办，上段仍为子 Agent 内容；③ 两段同时有数据时不串位；④ **实时**更新（无需手动刷新）；⑤ 中枢无待办时下段有明确空态 |
| **M6** | ① 节点执行失败能进 `experience_records`；② 同签名跨会话命中并注入；③ 环境签名不同的经验**不误伤**（降级为参考）；④ 派发前召回生效；⑤ 定时整理只产出草案，不自动写 resolved |
| **M7** | ① 改坏页面 → 文本反馈能定位（含 console 错误/失败请求/DOM 快照）；② 截图能作为产物回传并在前端查看；③ 无显示器环境下可运行（headless）；④ 依赖固化后节点无需 sudo 即可用 |

## 6. 降级链路

| 场景 | 降级行为 |
|------|---------|
| `verify.json` 缺失/非法 | 退回项目自带配置探测 → 再退回最小检查 → 都无则上报「无法验证」，**不判失败** |
| 某层验证超时 | 该层记为「未通过（超时）」，不静默跳过；是否阻断由判据的 `必过` 标记决定 |
| LSP 不可用 | 编辑照常成功，跳过诊断回灌 |
| 权限兜底拉取失败 | 记 warning，继续依赖推送；同时上报可观测信号（不得静默） |
| `hub.task_steer` 不被旧节点识别 | 旧节点忽略未知事件；预算闸退化为仅硬取消 |
| 经验库为空/服务异常 | 技能与召回降级为「无经验注入」，不影响任务执行（沿用 ADR-050 原则） |
| 模型不支持图片 | M7 降级为仅文本反馈 + 截图存档给人看 |
