# 任务与节点状态管理模块 Spec

## 1. 功能描述

维护系统中两类核心实体的状态：

- **任务状态**：描述任务从创建到归档的全生命周期。
- **节点状态**：描述 Agent 节点的在线/离线/负载状态。

状态管理是调度、监控、异常处理的基础，必须保证状态转换的原子性和可追溯性。

## 2. 用户故事

- 作为用户，我希望看到任务当前处于哪个阶段。
- 作为中枢，我需要根据任务状态决定是否允许分配、重试、迁移。
- 作为中枢，我需要根据节点状态决定任务是否可以下发。
- 作为运维，我希望追溯任意任务的历史状态变更。

## 3. 核心流程

### 3.1 任务状态机

```
            ┌─────────────┐
            │   pending   │
            └──────┬──────┘
                   │ 分配
                   ▼
            ┌─────────────┐
            │  assigned   │
            └──────┬──────┘
                   │ 开始执行
                   ▼
            ┌─────────────┐     失败      ┌─────────┐
            │   running   │──────────────▶│ failed  │
            └──────┬──────┘               └────┬────┘
                   │ 完成                        │ 重试
                   ▼                              │
            ┌─────────────┐◀─────────────────────┘
            │  completed  │
            └──────┬──────┘
                   │ 高风险待确认
                   ▼
            ┌─────────────┐
            │await_confirm│
            └──────┬──────┘
                   │ 确认
                   ▼
            ┌─────────────┐
            │  archived   │
            └─────────────┘
```

其他状态：`timeout`（超时）、`cancelled`（已取消）。

### 3.2 节点状态机

```
            ┌─────────────┐
            │   offline   │
            └──────┬──────┘
                   │ 注册/心跳恢复
                   ▼
            ┌─────────────┐
            │    idle     │
            └──────┬──────┘
                   │ 在跑任务数 > 0
                   ▼
            ┌─────────────┐
            │    busy     │
            └──────┬──────┘
                   │ 节点异常
                   ▼
            ┌─────────────┐
            │   error     │
            └─────────────┘
```

> **2026-09-12 修订（ADR-032）**：`busy` 降级为**纯展示态**（在跑任务数 > 0
> 即 busy），不再是调度排除条件——调度以「在线 + 资源水位 + 在跑数 <
> `max_concurrent_tasks`」判定（见 concurrent-task-scheduling-spec §3）。
> 节点可并发执行多个任务；`offline`/`error` 仍排除在调度之外。

## 4. 降级链路

| 异常场景 | 降级策略 |
|---------|---------|
| 任务状态更新失败 | 写入重试队列，记录错误日志，避免状态不一致 |
| 节点状态误判 | 结合心跳时间和任务上报综合判定，避免单点抖动 |
| 状态机非法转换 | 拒绝操作并返回明确错误码 |
| 并发状态冲突 | 使用数据库行锁或 Redis 分布式锁保证原子性 |

## 5. 验收标准

- [ ] 任务状态转换符合状态机定义，非法转换被拒绝。
- [ ] 节点状态随心跳自动更新，离线判定准确。
- [ ] 高负载节点不再接收新任务。
- [ ] 每个状态变更记录时间戳、触发原因、操作来源。
- [ ] 支持按状态筛选任务列表和节点列表。
