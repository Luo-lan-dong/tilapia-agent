# ADR-067 待办先行与派发确认门禁 · Spec

## 1. 用户故事

1. 作为用户，我说「开发登录页并部署」后，**第一眼**就在任务摘要看到中枢的全计划待办
   （1. 生成三件套 2. 创建任务 3. 报告等待确认 4. 派发 5. 跟踪 6. 验收…），而不是等 AI 干完活才出现。
2. 作为用户，AI 报告「等待你确认派发」后，**在我确认前任务绝不执行**——谁都不能悄悄派发。
3. 作为用户，我确认后（或任务队列手动派发）任务立即执行，流程不受影响。

## 2. 核心流程（修订后）

```
用户: 开发登录页并部署
  ▼
todo_write(add)  ← 挂当前会话（无任务也可用）
  1.[ ] 生成三件套规范文档
  2.[ ] 创建任务（阶段一）
  3.[ ] 向用户报告并等待确认派发
  4.[ ] 用户确认后派发到 code 节点
  5.[ ] 跟踪节点开发
  6.[ ] 验收与汇报
  ▼
todo_write(start,1) → generate_spec_docs → todo_write(complete,1)
  ▼
todo_write(start,2) → create_task（dispatch_hold=True，调度器跳过）
        └ 迁移：会话待办 1~6 → 挂到新任务（用户立即可见同一清单）
  ▼
todo_write(start,3) → 向用户报告「等待确认派发」（此时节点绝不执行）
  ▼
用户:「确认派发」 → smart_dispatch（dispatch_task 内清除 hold）
  ▼
todo_write 推进 4→5→6；任务终态 → ADR-066 唤醒轮继续编排
```

## 3. 边界

- API 直建任务（无编排 AI）不受 hold 影响——`dispatch_hold` 默认 False，行为不变；
- 手动派发（任务队列「派发」按钮走 dispatch_task）同样清除 hold；
- 待办迁移失败不阻塞创建任务（旁路告警）；
- 中枢待办列表合并逻辑：任务创建后待办已归属任务，前端查询无需改动。

## 4. 验收标准

1. 新会话说执行型需求：**第一条技能调用前**中枢待办已出现全计划（挂会话）；
2. create_task 成功后：待办自动归属新任务（task_id 非空），前端任务摘要可见同一清单；
3. create_task 后任务 `dispatch_hold=True`：调度器连续 3 个周期不派发；
4. 用户确认 → smart_dispatch 成功：hold 清除、任务正常执行；
5. 既有回归：todo_write 挂任务路径、API 直建任务自动派发均不回归。
