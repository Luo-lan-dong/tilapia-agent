# 中央调度中枢模块 Harness

## 1. 测试金字塔

```
        /\
       /  \
      / E2E \          少量：完整任务闭环
     /--------\
    /  集成测试  \       中量：调度 + 数据库 + Redis
   /--------------\
  /    单元测试     \      大量：拆解、匹配、状态机
 /------------------\
```

## 2. 单元测试清单

| 测试对象 | 测试场景 | 通过标准 |
|---------|---------|---------|
| 需求解析器 | 有效需求输入 | 输出任务类型、优先级、交付物列表 |
| 需求解析器 | 模糊需求输入 | 抛出 `RequirementParseError` |
| 任务拆解引擎 | 复合需求拆解 | 输出正确子任务树，串行/并行关系正确 |
| 任务调度引擎 | 存在空闲节点 | 返回最优节点 ID |
| 任务调度引擎 | 无可用节点 | 返回 `None`，任务进入等待队列 |
| 状态机 | 状态转换 | `pending → assigned → running → completed` 合法 |
| 状态机 | 非法状态转换 | 抛出 `TaskStateError` |

## 3. 集成测试清单

| 测试对象 | 测试场景 | 通过标准 |
|---------|---------|---------|
| 任务创建到分配 | 创建任务 → 拆解 → 匹配节点 | 数据库任务状态正确，Redis 队列有任务 |
| 进度上报聚合 | 模拟 Agent 上报进度 | 前端可收到 WebSocket 进度事件 |
| 节点离线迁移 | 模拟节点心跳中断 | 任务迁移到新节点，原节点任务状态更新 |
| 任务失败重试 | 模拟任务执行失败 | 重试 1 次后冻结并通知 |
| 交付物聚合 | 多个子任务完成 | 中枢生成完整交付包元数据 |

## 4. 契约测试清单

| 测试对象 | 测试场景 | 通过标准 |
|---------|---------|---------|
| Agent 注册接口 | 合法注册请求 | 返回 200，节点入库 |
| 任务下发消息 | 任务下发事件格式 | 符合 `api-standards.md` 消息格式 |
| 进度上报消息 | 进度事件格式 | 字段完整，类型正确 |
| 结果回传消息 | 交付物路径格式 | 符合文件路径规范 |

## 5. E2E 测试场景

### 场景 1：完整任务闭环

1. 用户在前端提交需求「开发一个企业官网」。
2. 中枢拆解为需求分析、UI 设计、前端开发、后端开发、部署 5 个子任务。
3. 各子任务分配给对应 Agent 节点。
4. 用户在前端看到实时进度。
5. 所有子任务完成，中枢聚合交付物。
6. 用户下载完整项目包。

### 场景 2：节点故障自动迁移

1. 编程 Agent 正在执行任务。
2. 模拟该 Agent 网络中断 30 秒。
3. 中枢标记节点离线。
4. 任务自动迁移到另一个空闲编程 Agent。
5. 用户收到系统告警通知。

## 6. CI 门禁

- 单元测试覆盖率 ≥ 70%。
- 所有集成测试通过。
- ruff / black / mypy 检查通过。
- API 契约测试通过。
