## 4. 边界与不做项

- **不重复实现** ADR-064 的 `@节点` 续聊会话能力；仅对齐其 `POST /api/v1/tasks/{id}/agent-trace` 上报契约与 seq 语义（064 已定：该端点无任务状态前置，仅校验任务存在）。
- **模板化**（企业模板/母版/品牌色）按 D3 **延后至第二批**，本批只预留接口位。
- 不扩展 stage 枚举（沿用 ADR-062 封闭集：`planning`/`searching`/`coding`/`summarizing`/`idle`）。
- **M7 终态裁决（主会话，2026-10-05）**：Spec 降级链路 D5 原写「预算耗尽 → 进入阻断态」，实现改为 **`failed`（原因 `budget_hard_exceeded: 已用 X/Y tokens，N 轮`）+ 同事件附 `usage`**。理由：① 满足「不得假装成功」硬要求；② 中枢 `verify_blocked` 语义是"验收未通过、等用户在 24h 内决定接受现状/继续修复"，而预算耗尽是**资源约束、无"接受现状"可言**，套用会让前端决策入口误导用户；③ 与编程节点 ADR-061 M5b 硬停语义一致。**按规则以文档对齐实现**：Spec D5 的"阻断态"表述以本条为准（如需 D5 字面语义，另立小变更）。另：token 超限**不再多跑一轮收尾 LLM**（轮次上限路径行为不变）；`usage` 行每任务 1 条、`rounds` 取各次执行最大值。
- **主会话独立复验（每模块均独占执行）**：M1 **50** · M2 **69** · M3 **87** · M4 **111** · M5 **128** · M6 **153** · M7 **162**（全部 `0 failed`、`exit 0`）。
- **不属于本 ADR 的既有红点（已核实）**：中枢 `pytest -q -k office` = **6 passed**，但 `tests/services/test_task_service_spec_agent_type.py` 在 `db_session` 清理阶段抛 `ForeignKeyViolationError: fk_task_orchestrator_todos_sessions_session_id`——该表/外键由**并行推进的 ADR-067 迁移**引入（`conftest.py:264-271` 未按 `session_id` 清 `task_orchestrator_todos`），与 ADR-065 无关，需 ADR-067 负责方处理。
