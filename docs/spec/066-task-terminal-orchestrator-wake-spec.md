# ADR-066 任务终态自动唤醒编排 · Spec

> 用户故事核心：多阶段需求（「开发登录页 → 部署到云服务器」）中，节点完成阶段一后，中枢**自动**
> 核对交付物、推进待办、向用户汇报，并主动询问是否进入阶段二——而不是等用户发消息才动。

## 1. 功能描述

任务终态（completed/failed）时，中枢自动向任务关联的构建会话注入一条系统触发消息，
后台执行一轮编排（复用 ADR-033 技能链）：核对任务状态与交付物 → 用 todo_write 推进中枢待办 →
向用户汇报结果 → 存在下一阶段时列出计划等待用户确认。

## 2. 用户故事

1. 作为用户，我派发「开发登录页，完成后部署到云服务器」，阶段一完成时中枢**主动**告诉我
   「login_1006.html 已完成，修改摘要是…，是否开始部署？」，而不是我盯着「跟踪执行」待办发呆。
2. 作为用户，任务失败时中枢**主动**告诉我失败原因与建议，而不是等我追问。
3. 作为用户，我可以在设置页一键关闭自动唤醒（不想要自主推进时）。
4. 作为用户，我正在打字对话时唤醒轮不会打断我（互斥保护，稍后重试）。

## 3. 核心流程

```
节点上报 agent.task_completed / agent.task_failed
        │
        ▼
task_event_handler 落库任务终态（既有）
        │  落库成功后
        ▼
orchestrator_wake_service.schedule_wake(task_id)   ← asyncio.create_task，不阻塞
        │
        ▼
┌─ 唤醒前置检查（全部通过才执行）────────────────────┐
│ ① orchestrator_auto_wake_enabled 开关              │
│ ② tasks.session_id 关联会话存在                    │
│ ③ build 模式 + completed/failed                    │
│ ④ 同链 24h 唤醒 ≤5 次且连续失败唤醒 ≤3 次          │
│ ⑤ 会话无活跃前端流（steering），占用则延迟重试×3   │
└──────────────────┬─────────────────────────┘
                   ▼
   自建 Session → OrchestratorService(session)
   消息 = 会话历史尾部 + [系统自动唤醒] 触发消息
                   │
                   ▼
   chat_stream 后台消费（复用技能链：get_task_status / todo_write / …）
                   │
                   ▼
   落库 task_building_sessions.messages：
   [系统自动唤醒] 触发消息(user) + AI 回复(assistant, 含 thinking/steps)
                   │
                   ▼
   前端打开会话 / 轮询 → 看到汇报与已推进的待办
```

降级链路：LLM 配置缺失/调用失败 → 唤醒轮记 warning 后静默结束（不影响任务状态机）；
steering 占用重试 3 次仍失败 → 放弃本轮并记审计；同链超限 → 停止自动唤醒并记审计。

## 4. 边界（明确不做）

- 唤醒轮**不自动创建/派发**新任务（下一阶段询问用户，对齐 ADR-033 准则 11）；
- `verify_blocked` / `review` / `cancelled` 终态不触发（各自已有决策/审批入口）；
- 无关联会话的任务（API 直建）不触发；
- 唤醒轮不修改任务状态机、不触碰验收判据。

## 5. 验收标准

1. 真实任务 completed 后 ≤10s 内，会话出现「[系统自动唤醒]」消息与 AI 汇报；
2. 中枢待办「跟踪执行」项被 AI 标记 completed（todo_write 实际调用）；
3. failed 任务同样收到汇报（含失败原因与建议）；
4. 设置页关闭开关后，任务终态不再触发唤醒；
5. 连续 3 次同链失败唤醒后第 4 次不再自动唤醒（审计可见）；
6. 唤醒轮执行期间用户消息可正常排队（steering 互斥不 500）。
