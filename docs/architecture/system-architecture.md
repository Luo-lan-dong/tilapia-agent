# OPC 项目系统架构设计

## 1. 设计原则

- **四层分布式架构**：用户交互层、中央调度中枢层、专业 Agent 执行层、统一数据文件底座。
- **节点隔离**：每个 Agent 节点独立部署，硬件、运行环境、任务完全隔离。
- **唯一通信主体**：所有 Agent 节点只与中央调度中枢通信，节点之间禁止直接交互。
- **大文件走共享存储**：接口只传输文本、路径、状态数据，不传输大文件。

## 3. 各层职责

### 3.1 用户交互层

唯一人机交互入口，不参与任务执行与调度：

- 自然语言需求提交
- 全局任务看板
- 任务进度查询
- 交付物预览下载
- 高风险操作人工确认

### 3.2 中央调度中枢层

系统唯一调度核心，不执行具体业务任务：

- **需求解析器**：识别任务类型、执行要求、输出标准。
- **任务拆解引擎**：将复合任务拆分为独立可执行子任务。
- **节点注册中心**：管理 Agent 节点上下线、能力标签、负载状态、心跳检测。
- **任务调度引擎**：基于任务类型、节点能力、负载状态匹配最优节点。
- **任务队列管理**：支持优先级、排队、超时管控、失败重试策略。
- **流程编排模块**：管控多 Agent 协作逻辑、任务依赖关系、分支流程。
- **结果聚合模块**：汇总多节点产出物，整合为完整交付成果。
- **异常管控模块**：处理节点离线、任务报错、执行超时、任务迁移。

### 3.3 专业 Agent 执行层

采用**单节点单工种**设计，每台设备独立部署专属运行环境：

| 节点类型 | agent_type | 主要职责 |
|----------|-----------|---------|
| 编程 Agent | `programming` | 项目搭建、代码开发、BUG 修复、接口调试、部署 |
| 视频 Agent | `video` | 脚本生成、素材制作、视频剪辑、配音字幕、成片渲染 |
| 文案 Agent | `copywriting` | 短视频脚本、软文、公众号文案、产品介绍 |
| 设计 Agent | `design` | LOGO、海报、UI 界面、宣传物料、配图生成 |
| 运营 Agent | `operations` | 内容复盘、数据统计、渠道素材批量生成 |
| 商务财税 Agent | `business_finance` | 报价单、合同、收支台账、利润统计 |

通用节点能力：

- 任务接收
- 沙箱独立执行
- 进度实时上报
- 结果归档
- 日志记录
- 异常回传

### 3.4 统一数据文件底座

全局统一共享底层，为所有节点提供标准化数据、文件支撑：

- **任务数据库**：PostgreSQL，存储全量任务信息、执行状态、节点日志、操作记录、流程轨迹。
- **业务知识库**：PostgreSQL，存储 OPC 公司资料、行业模板、历史案例、规范标准。
- **统一文件存储**：MinIO，集中存放素材、代码工程、视频、文档、交付成果。

## 4. 通信规则

- 唯一通信主体：中枢 ↔ 各 Agent 节点。
- 节点之间禁止直接通信、直接分配任务、直接传输数据。
- 大文件统一走共享存储，接口仅传输文本、路径、状态数据。

## 5. 核心接口

| 接口 | 方向 | 说明 |
|------|------|------|
| 节点注册接口 | Agent → Hub | 节点开机主动上报设备信息、能力标签、硬件配置 |
| 心跳上报接口 | Agent → Hub | 节点定时推送在线状态 |
| 任务下发接口 | Hub → Agent | 中枢推送任务信息、执行要求、资源路径 |
| 进度上报接口 | Agent → Hub | 节点实时同步任务执行进度、日志信息 |
| 任务完结接口 | Agent → Hub | 节点回传任务状态、交付物路径、执行结果 |
