# OPC 项目部署架构设计

## 1. 设计目标

- MVP 阶段最小化部署成本，跑通完整任务闭环。
- 节点物理/逻辑隔离，符合「一工种一节点」原则。
- 便于后续横向扩容和故障迁移。
- 统一共享存储，避免节点间点对点传大文件。

## 3. 节点资源配置建议

| 节点 | 数量 | CPU | 内存 | GPU | 存储 | 说明 |
|------|------|-----|------|-----|------|------|
| 中央调度中枢 | 1 | 4 核 | 16GB | 无 | 100GB SSD | 同时跑后端、PostgreSQL、Redis |
| 编程 Agent | 1 | 8 核 | 32GB | 可选 | 200GB SSD | 全栈开发、调试、部署 |
| 视频 Agent | 1 | 8 核 | 32GB | 推荐 | 500GB SSD | 视频渲染、图像生成 |
| 文案 Agent | 1 | 4 核 | 16GB | 无 | 100GB SSD | 文案生成 |
| 统一共享存储 | 1 | 4 核 | 8GB | 无 | 2TB+ | MinIO 对象存储 |

> 注：MVP 阶段最小集群，无冗余部署。生产环境需按高可用架构扩展。

### 4.1 服务容器拆分

| 容器 | 镜像 | 说明 |
|------|------|------|
| `opc-web-console` | `opc/web-console` | React 前端静态服务 |

### 4.2 Docker Compose 文件组织

```
docker-compose.yml              # 基础服务：hub、postgres、redis、minio

docker-compose.staging.yml      # 预发布环境
docker-compose.prod.yml         # 生产环境（外部数据库/Redis/MinIO）
```

## 5. 生产环境演进方向

### 5.1 高可用中央调度中枢

- 后端服务多实例部署，前置 Nginx/Traefik 负载均衡。
- PostgreSQL 主从复制或使用托管数据库服务。
- Redis Cluster 或 Sentinel 高可用。

### 5.2 Agent 节点池化

- 同类型 Agent 节点部署多台，形成节点池。
- 中枢根据负载动态选择最优节点。
- 节点离线时任务自动迁移到池内其他节点。

### 5.3 共享存储扩展

- MinIO 分布式部署，支持多磁盘、多节点。
- 或迁移到云厂商 S3 兼容对象存储。

### 5.4 网络隔离

- 中枢与 Agent 节点部署在私有网络（VPC）内。
- 前端通过 API 网关访问中枢。
- Agent 节点注册必须携带 Token 或证书。

## 6. 端口规划

| Redis | 6379 | 内部暴露 |
